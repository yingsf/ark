# Recheck Guidelines

本文件承载 `/ark:ark-review` 的复审流程。用户说“已修复，请重新审查 / 复审 / 再检查”时必须执行。

## 复审输入

复审时必须读取：

- 上一轮 Findings
- 本轮用户说明的修复范围
- 对应修复代码
- 新增或更新的测试
- 相关任务契约、设计约束和验证结果

缺少上一轮 Findings 或修复范围时，应在 `Open Questions` 中说明判断限制，但仍尽力审查当前 diff。

## 闭合检查

逐条检查上一轮 Finding：

1. 找到对应修复代码
2. 判断修复是否真正闭合原问题，而不是只调整测试或局部表象
3. 检查是否补了修复前会失败、修复后会通过的回归测试
4. 检查修复是否扩大影响面
5. 检查是否破坏原有主路径、默认行为、权限边界、状态语义或跨层口径

## 新风险检查

复审时必须寻找修复引入的新问题：

- 为修复边界 case，把主路径排序、过滤、状态机改坏
- 为避免重复计数，改成漏计
- 为避免空值报错，改成 fail-open
- 为通过测试，把 fake repository / helper 改到和真实 repository 行为不一致
- 只补 happy path 测试，没有覆盖上一轮问题的反例
- 修复点绕开了任务契约或改变了默认范围

## 输出要求

- 在 `Findings` 中输出新发现或未闭合的问题
- 在 `Verification` 中列出复审实际运行的命令
- 在 `Open Questions` 中列出无法确认的旧问题或缺失上下文
- 在 `Verdict` 中明确说明上一轮问题是否已闭合
- 旧问题闭合不代表自动放行；若修复引入新风险，应作为新的 Finding 输出
