# Project Reality Policy

本文件定义 ARK 如何识别项目类型、记录真实性锚点，并把实现与验证尽早拉回真实运行闭环。

## 目标

ARK 不应只产出能通过单元测试的占位代码。对需要真实依赖、真实入口或真实数据才能证明价值的项目，plan、tasks、implement、test、validate 必须尽早建立最小真实闭环。

同时，ARK 也不能把所有项目都强行套入"后端 + 数据库 + 数据目录"模型。库、CLI、前端、插件、数据/AI 项目都有不同的真实性锚点。

## 项目画像

项目画像用于描述当前项目的真实工作方式，不是新的核心 Artifact。默认记录在项目 `CLAUDE.md` 的 `ARK 项目画像` 小节中；已有项目可由 `/ark:ark-init` Mode B 或 `/ark:ark-analyze` 补充/更新建议。

画像字段：

| 字段 | 含义 |
|------|------|
| 项目类型 | backend service / library SDK / CLI / frontend / data-AI / plugin / mixed / unknown |
| 运行入口 | 实际启动、导入、命令行、浏览器或宿主加载入口 |
| 依赖形态 | 数据库、缓存、搜索、队列、第三方 API、文件系统、浏览器、宿主程序等 |
| 数据源 | 仅记录路径/来源/脱敏状态/样例规模/访问方式，不记录敏感数据内容 |
| 契约边界 | HTTP/MCP/API/CLI/SDK/文件格式/事件等对外契约 |
| 真实验证方式 | 最小真实闭环、集成验证、端到端验证或包安装验证 |
| 替身边界 | mock、fake、内存实现、样例数据等替身允许出现的位置和退出条件 |

## 项目类型与真实性锚点

| 项目类型 | 真实性锚点 |
|----------|------------|
| backend service | 服务能按实际入口启动；配置能加载；关键外部依赖可连接或被明确标记为替身；核心 API 可被真实调用 |
| library SDK | 包能安装/导入；公开 API 契约可被调用；必要时用本地测试服务验证协议行为 |
| CLI | 命令能真实执行；参数、文件输入、退出码、stdout/stderr 可验证 |
| frontend | 应用能在浏览器运行；关键交互、接口调用、视图状态可验证 |
| data-AI | 数据源元信息明确；真实样例数据可访问或缺失原因明确；解析/编译/评估链路有可复现证据 |
| plugin / framework extension | 宿主能加载；生命周期钩子、配置和边界行为可验证 |
| mixed | 按本次任务涉及的子系统选择多个真实性锚点 |
| unknown | 先通过 `/ark:ark-analyze` 或 `/ark:ark-intake` 缩小类型，不得默认套用后端模型 |

## 数据源规则

- ARK 不创建、不迁移、不托管项目数据目录。
- `data/`、`datasets/`、对象存储、本地绝对路径、测试夹具等均属于项目管理范畴，是否提交 git 由项目决定。
- ARK 文档只记录数据源元信息：位置、格式、样例规模、敏感性/脱敏状态、访问方式、验证时使用的样本范围。
- 不得把敏感原始数据、密钥、连接串或大体量数据内容写入 Artifact 或扩展文档。
- 当功能与数据强相关时，plan/tasks/implement/validate 必须说明使用真实数据、脱敏样例、合成数据或 mock 数据，并给出真实性影响。

## 替身规则

替身包括 mock、fake、in-memory repository、stub server、合成数据和临时占位实现。

允许使用替身的情况：
- 需求澄清、接口探索、单元测试隔离、不可用依赖的短期替代
- 真实依赖暂不可访问，但替身边界和退出条件已记录

禁止使用替身的情况：
- 把替身结果报告为真实验证通过
- 在任务链路很长时持续推进业务代码，却没有计划接入真实入口/真实依赖/真实数据
- spec、design、plan 已承诺真实依赖或真实数据，但 tasks 没有对应接入与验证任务

替身债务必须记录退出条件：什么依赖、数据、配置或契约满足后替换，替换后如何验证。

## 验证保真度

`/ark:ark-validate` 和相关 Skill 应按以下等级描述证据强度：

| 等级 | 含义 |
|------|------|
| L0 | 静态检查、格式化、类型检查 |
| L1 | 单元测试，可能使用 mock/fake |
| L2 | 组件级验证，使用真实组件或真实文件格式 |
| L3 | 集成验证，使用实际配置和关键外部依赖 |
| L4 | 最小真实闭环，按项目实际入口完成核心路径 |
| L5 | 生产等价或预发布环境验证 |

mock/fake 证据最高只能支持"替身环境通过"，不能替代 L3/L4/L5 结论。

## Skill 职责

| Skill | 职责 |
|-------|------|
| `/ark:ark-init` | 初始化时生成或建议项目画像；Mode A 询问项目类型，Mode B 基于已有文件推断 |
| `/ark:ark-analyze` | 重新识别项目类型、入口、依赖、数据源信号和真实性锚点 |
| `/ark:ark-spec` | 将真实性要求写入验收标准，而不是只写"功能正常" |
| `/ark:ark-design` | 说明真实依赖、数据流、契约边界和替身边界 |
| `/ark:ark-plan` | 优先安排最小真实闭环，不让真实基础设施或数据无限后置 |
| `/ark:ark-tasks` | 只维护当前窗口任务，并给任务标注真实性锚点和验证等级 |
| `/ark:ark-implement` | 开始前做 Reality Check；实现后识别替身债务和文档漂移 |
| `/ark:ark-test` | 根据项目类型选择合适测试形态，区分 mock 测试与真实组件测试 |
| `/ark:ark-validate` | 严格区分验证等级，不把替身证据写成真实通过 |
| `/ark:ark-sync` | 检查项目画像、核心 Artifact、扩展文档与代码现实是否失真 |

## 非目标

- 不强制所有项目都接入数据库、搜索、消息队列或数据目录。
- 不替用户管理项目数据。
- 不因为真实环境暂不可用而阻塞所有开发，但必须暴露真实性缺口。
- 不把项目画像变成第 8 个核心 Artifact。
